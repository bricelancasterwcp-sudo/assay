# assay v1.10 — the semantic-break registry

2026-08-18. Brainstormed immediately after v1.9's whole-branch review,
which found the defect this wave closes and recorded it rather than
fixing it (v1.9's CARRIED-DEBT section, "the diff blind spot"). Scope
confirmed by Brice 2026-08-18: the registry approach, stacked on v1.9 so
the rule change and its guard ship together. Ships as **0.12.0, profile
schema unchanged at v10**.

One component: `diff` learns that a cell can stop meaning what it meant,
and refuses to score one across the break.

## §0 Scope and non-goals

In scope: a registry of cells whose measurement rule changed and the
version each changed at; the comparison-time check that consults it; a
new `DiffResult` field naming what was incomparable; the exit-code and
render consequences; and the tests that pin all of it.

Non-goals: **extending `identity_gate`** — a version difference is not a
different endpoint, and making it fatal would kill the cross-upgrade
diffs the instrument exists for (§5). **Any change to schema v10, the
parallel family, `classify_mode`, or `verdict.parallel`'s ladder** —
v1.9 settled those and this wave only teaches `diff` to respect the
break v1.9 created. **Backfilling breaks for earlier versions** — every
bump before v1.9 was additive; §1 says why that means the table starts
with one row. **Re-running any campaign or rescoring any profile.**

## §1 The defect

`diff` compares five families — ceiling, ceiling_shapes, verdicts,
codecs, speed — and scores each cell by the strongest evidence it
carries. It has no notion of *which instrument produced the numbers*.
`identity_gate` establishes that both documents describe the same model
on the same class of machine; it says nothing about whether the two
runs meant the same thing by what they wrote.

Until v1.9 that was harmless, because every schema bump had been
**additive**: a new release measured cells the old one did not, so the
old side simply lacked them, they landed in `dropped`, and v1.8's exit 3
reported the comparison as incomplete. The machinery worked because
absence is visible.

v1.9 is the first release to change **what an existing cell means**
without changing its name, its type, or its presence. `classify_mode`
went from an absolute-seconds overlap test to a fraction-of-span one, so
`parallel.rows[].mode` — and through it `verdict.parallel` — can read
differently for an endpoint that did not change at all. Both sides
measured the cell, so nothing is absent, so nothing is dropped, so exit
3 cannot fire.

Reproduced, same model and box, a 0.10.0 baseline against a 0.11.0
re-run on a fast endpoint:

```
comparable: True   identity notes: ()
verdict.parallel: risky -> ready (improvement, flip)
exit plain: 1      exit --gate: 0
```

An instrument change published as a fact about the endpoint, and
`--gate` passing it silently because improvements do not fail a gate.
The affected population is exactly the one v1.9 exists to serve:
endpoints fast enough to have hit the old cliff.

## §2 The registry

A module-level table in `diff.py` mapping a diff cell's name to the
version at which its meaning changed:

```python
#: Cells whose MEASUREMENT RULE changed at a given probe version, so a
#: pair straddling it was measured under two different definitions and
#: no arithmetic between the two sides is a fact. Keyed by the cell name
#: `diff` already uses (``f"{family}.{cell}"``); the value is the first
#: version that used the NEW rule, parsed, because "0.9.0" < "0.11.0" is
#: False under string comparison.
#:
#: This table is small BY CONSTRUCTION and is expected to stay small: an
#: entry is needed only when a release changes what an existing cell
#: means. Every bump before v1.9 was additive — a new cell the old side
#: lacked, which `dropped` and exit 3 already handle — which is why one
#: row covers eleven releases.
SEMANTIC_BREAKS: dict[str, tuple[int, ...]] = {
    # v1.9 (0.11.0): classify_mode moved from an absolute-seconds
    # overlap test to a fraction of the shorter span, so `mode` — and
    # the verdict derived from it — can differ for an unchanged
    # endpoint.
    "verdict.parallel": (0, 11, 0),
}
```

Versions parse with a small helper that returns `None` for anything it
cannot read. **Parsed, never compared as strings**: `"0.9.0" < "0.11.0"`
evaluates to `False`, which would make the check silently wrong in the
direction of scoring a broken pair.

## §3 What a straddle does

A pair **straddles** a break when one side's `probe_version` is below
the break version and the other is at or above it. Order does not
matter: an upgrade and a downgrade are equally incomparable.

A straddled cell is **not compared**. It is not scored as a change and
not recorded as checked-and-clean. Both sides hold a number; the numbers
answer different questions.

## §4 A new field, not a widened one

v1.8 established, enumerated and mutation-tested a load-bearing
invariant:

> `dropped` is non-empty **iff** some cell was measured on exactly one
> side.

Exit 3 reads it directly. Folding semantic breaks into `dropped` would
silently widen it to "…or was measured under a rule that has since
changed", breaking an invariant a previous wave went to real trouble to
establish, and leaving a reader unable to tell the two apart.

So `DiffResult` gains a field:

```python
    #: Cells NOT compared because the two documents were measured under
    #: different definitions of them (§2's registry). Distinct from
    #: `dropped`, which means measured on exactly one side: there, one
    #: side has nothing to say; here, both sides speak and they are not
    #: speaking about the same thing.
    incomparable: tuple[str, ...] = ()
```

`_diff_exit_code` fires **3** on `dropped or incomparable`, keeping its
existing precedence `2 > 3 > 1 > 0`. `render_diff` names the two causes
separately — a reader must be able to act on the difference, because a
one-sided cell is fixed by re-running and an incomparable one is not.

The `--json` document gains the field for the same reason it already
carries `within_noise`: a machine reader needs to know what was compared
and what was not.

## §5 What does not change

**`identity_gate` is untouched.** It answers "are these the same model
on the same class of machine", and a version difference is not a
different endpoint. Making it fatal would return exit 2 for every
cross-upgrade pair and destroy the instrument's central use — tracking
one endpoint's drift across releases. The gate's five checks stay as
they are.

**Additive bumps behave exactly as today.** A cell absent on one side
still lands in `dropped` under v1.8's rule; a release with no registry
entry compares as it always did. This wave adds a reason a comparison
can be incomplete; it removes none and changes no existing one.

**Exit-code meanings are unchanged**: 0 clean, 1 drift, 2 not
comparable, 3 incomplete, 4 unreadable. Only the set of conditions that
can produce 3 grows, which is why the change needs no new code and no
consumer has to learn a new number.

**Schema stays v10.** Nothing about a *profile* changes; this is a
change to how two profiles are compared.

## §6 An unknown instrument is not a comparable one

A profile whose `probe_version` is missing, `None`, or unparseable is
treated as straddling **every** break. Absence is not evidence of
sameness: "we could not establish which rule produced this" must resolve
to *not comparable*, never to *comparable by default* — the same
discipline the rest of the instrument applies to an absent measurement.

No committed profile hits this path today. All four evidence directories
were checked: every profile carries `probe_version`, across five
distinct values (`0.1.0`, `0.3.0`, `0.4.1`, `0.5.0`, `0.9.0`). The path
is nonetheless real for a hand-written or truncated document, and is
tested.

## §7 Testing posture

House rules apply (TDD; mutation-check each load-bearing test).
Specifically:

- **The straddle in both directions.** `0.10.0` against `0.11.0` and
  `0.11.0` against `0.10.0` must both yield an incomparable
  `verdict.parallel` and exit 3. Testing one direction would leave a
  half-correct comparison passing.
- **Both-sides-old and both-sides-new compare normally.** Two 0.10.0
  documents, or two 0.11.0 documents, must score `verdict.parallel` as
  they do today. This is what stops the guard becoming always-on, which
  would be its own kind of useless.
- **Version ordering is parsed, not lexical**, pinned with the exact
  pair that gets it wrong: `0.9.0` must compare as below `0.11.0`. A
  string comparison returns `False` here and would silently score a
  broken pair.
- **A missing or unparseable `probe_version` is incomparable** (§6).
- **`dropped` and `incomparable` stay distinct**: a pair that has one
  cell measured on one side only AND one cell straddling a break must
  report each in its own field, and exit 3 once.
- **The end-to-end reproduction from v1.9's review**: the pair that
  today reports `verdict.parallel: risky -> ready (improvement)` with
  `--gate` exit 0 must become exit 3 with the cause named. This is the
  test that proves the wave did what it exists to do.
- **Every other cell in a straddled pair still compares.** The break is
  per-cell, not per-document: a v1.9 boundary must not stop `diff`
  scoring `ceiling`, `speed` or the codec cells, whose rules did not
  change.
