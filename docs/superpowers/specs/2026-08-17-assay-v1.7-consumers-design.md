# assay v1.7 — consumers and the matrix

2026-08-17. Third of three waves from the 08-14 brainstorm (v1.5
instrument-sharpening SHIPPED → v1.6 agent surface SHIPPED → **v1.7
consumers + matrix**), scope re-confirmed with two Brice additions on
08-17: the tier re-profile campaign and the tools sequential
generalization. Ships as **0.9.0, profile schema v8**.

Six components: sequential look-schedule sampling for the tools family
(scripted-tools-v2), deeper JSON codec grades (codec-fixtures-v3), a
parallel-degradation family, a time/call-budgeted probe mode, the
capability matrix published on GitHub Pages, and a full re-profile
campaign of the tier-enthusiast directory that feeds it. The wave's
theme: make the instrument cheap enough for applications to consult
and publish what it measured.

## §1 Tools sequential looks — scripted-tools-v2

v1.6 shipped `tool_calling` at fixed n=5: five-of-five reads
ready-provisional because Wilson at n=5 spans the ready/risky
boundary. The blocker named in v1.6 §6 was not the stats machinery —
`LOOK_SCHEDULE`, `wilson95`, `decided` in `assay.stats` already serve
the codec cells — it was that five scripted tasks cannot honestly
yield n=20: at pinned temperature 0.2, re-running the same five tasks
with fresh seeds measures sampler variance, not capability.

**The pool grows; the tools do not.** `TASKS` grows 5 → 20.
Invariants:

- Tasks 0–4 are the v1 pool **verbatim, in order**. Quick mode scores
  exactly tasks 0–4 with the v1 seeds, so quick-mode numbers remain
  comparable across the boundary and the committed tools-anchor
  captures replay byte-identically.
- `TOOLSET` and `TOOLSET_NAME` (toolset-v1) are FROZEN. The pool is
  part of the instrument's identity instead: `TOOLS_INSTRUMENT`
  becomes `scripted-tools-v2`, and the lens carries it.
- Every new task obeys the v1 authoring law: one obviously-correct
  tool; the file or query named VERBATIM in the user message so the
  pinned-argument check stays mechanical; the pool mixes repeated
  tools with different argument values and includes no-argument
  `run_tests` cases, so a memorised call shape scores differently from
  reading the request.
- Seeds stay `seed_base + i` / `seed_base + 100 + i` — the existing
  scheme already keys 20 tasks without collision (T1 seeds 1400–1419,
  T2 seeds 1500–1519).

**Sequential decision.** Looks at {5, 10, 20} — a truncation of
`LOOK_SCHEDULE` (the pool bounds the last look; the lens says so).
The decision metric is the COMPOSITE (the ladder metric): at each
look, if `decided(round(composite * n), n)` per the existing rule,
stop. Full mode defaults to sequential; quick keeps fixed n=5. The
lens carries `n_used` and `stopping_rule`
(`sequential-{5,10,20}` / `fixed-n`), exactly as codec lenses do.
`result_use_rate` and the stop counters ride at whatever n the T2
turns reached — they are not decision inputs.

**Cost.** Worst case 40 calls (20 tasks × 2 turns), inside the
500-call full default beside every other family's spend.

Falsification tests: a scripted backend at composite 1.0 stops at the
first decided look, never runs all 20; a backend that hovers at the
boundary runs to the cap and reports provisional; quick-mode replay of
the committed anchor is byte-stable; every new task's pinned argument
appears verbatim in its user message (checked mechanically over the
pool, the same test shape v1.6 used).

## §2 Deeper JSON — codec-fixtures-v3

Three new `json_object` grades beside the existing flat ones:

- `nested` — one object, 2–3 levels of nesting.
- `tabular` — an array of homogeneous objects, fixed length.
- `constrained` — flat, but with enum-valued fields and a
  required-keys-no-extras contract.

Five fixture variants per grade, authored under the fixtures-v2
heterogeneity discipline; the set name in lens and provenance becomes
`codec-fixtures-v3`. **v2 cells are byte-untouched** — every existing
fixture, grade, and cell keeps its identity so `assay diff` across the
version boundary compares like with like.

The verdict does not move: `structured_extraction` ladders on the same
cell it does today (`_GRADE_FOR_VERDICTS`). The new grades are new
COLUMNS — profile cells and matrix columns — not a silent
redefinition. Sequential sampling applies to the new cells exactly as
to any codec cell.

Falsification tests: the v2 fixture bytes are pinned (a v3 authoring
edit that touches a v2 fixture fails); each new grade's fixtures parse
and round-trip under the applies lens' own checker before any model
sees them; the verdict cell mapping is pinned so adding grades cannot
move it.

## §3 Parallel degradation — the `parallel` family

The agent-fleet question: what happens when k requests hit the
endpoint at once. New probe family, **measurement-only** (no verdict
this wave).

Instrument: for k ∈ {2, 4}, k lanes each send the pinned
`DECODE_PROMPT` concurrently (stdlib `threading`; distinct pinned
seeds per lane so lanes are distinguishable in a transcript). Metrics
come from **server-reported timings** per lane, the same source and
fallback-class discipline as `assay.speed`:

- `per_lane_decode_tps` — mean over lanes, per k.
- `total_throughput_tps` — sum over lanes, per k.
- `degradation_ratio` — per-lane tps over the SAME RUN's single-lane
  `speed.decode_tps` (the speed family is this family's baseline and
  must have measured; otherwise the family drops with
  "parallel: no single-lane baseline").
- `mode` — `parallel` vs `serialized`, decided from lane wall-time
  overlap: if lane completion times stack (each lane's span begins
  after the previous ends, within tolerance), the endpoint queued
  them. The overlap tolerance is a CHOSEN constant, marked provisional
  in the family payload until the campaign's live rows let it be
  sanity-checked — thresholds are derived, not chosen, and a chosen
  one is flagged. For a consumer this is the headline: a serialized
  endpoint doubles latency at k=2 rather than sharing throughput.
- Failure classes per lane: an errored lane is infrastructure evidence
  (named), never a zero in a mean. Missing server timings under
  concurrency → the evidence class says so, no client-clock guesses
  for tps (client wall-clock is used ONLY for the serialized/parallel
  overlap fact, which is a scheduling observation, not a rate).

Schema: `parallel` is a new post-v1 family (absent in old profiles →
named in `dropped` on parse, per the existing `_POST_V1_FAMILIES`
mechanism). Runs in full mode only; ~1 warmup + 6 lane calls.

Falsification tests: serialized-vs-parallel classification pinned
against synthetic timing sets on both sides of the tolerance; an
errored lane drops out of the mean AND is named; the family refuses to
run without the baseline; degradation arithmetic pinned on committed
synthetic rows.

## §4 Budget mode — the consumer probe

The consumer story (from the VTT AI audit): an application at
settings-time wants the most load-bearing profile it can get in ≤N
calls, optionally ≤S wall-clock seconds.

- CLI: `assay probe ... --budget-calls N [--budget-seconds S]` →
  provenance `mode: "budget"`. Library: `mode="budget"` with the
  existing required `budget=` carrying the numbers. `Budget` gains
  `max_seconds: float | None = None`; the meter learns a clock check
  applied BETWEEN calls only — a call in flight is never cut.
- **Pre-registered family priority**, cheapest and most load-bearing
  first: geometry → envelope → speed → `json_object` quick cells →
  patch-codec quick cells → tools quick → ceiling → loop →
  long_output.
- Family preflight: before a family starts, its worst-case call cost
  (a constant the family declares) is checked against the remaining
  meter; a family that does not fit is **dropped by name** —
  `"<family>: budget — would exceed remaining"` — never started and
  truncated mid-family. What starts, finishes (the seconds ceiling
  also checks only at family boundaries and between calls; on trip,
  remaining families drop by name with "budget: seconds").
- Verdicts need no change: unmeasured families read `unmeasured`
  through the existing None-vs-zero path. Provenance records granted
  vs spent including seconds.

Falsification tests: a worked example is pinned — at N=25 on a
scripted backend, exactly {geometry, envelope, speed, json quick}
measure and every other family's drop line names the budget; the
priority order is pinned as data (reordering fails a test); an
injected clock proves the seconds ceiling never interrupts a family
mid-call and stamps the drop reason.

## §5 The matrix on GitHub Pages

- `scripts/build_matrix.py` (stdlib): renders `assay report` over
  `docs/superpowers/evidence/tier-enthusiast-2026-08/*.json` into
  `docs/matrix/index.html`, committed. Pages serves master `/docs`;
  README links the live URL beside the evidence directory.
- Report polish riding along: page `<title>`, a short intro paragraph
  (what the matrix is, the instructed-behavior caveat, probe version
  and capture dates), links back to the repo and to the errata files.
  Provisional cells keep rendering as provisional — a page of decided
  rows is the goal of the campaign, not a rendering trick.
- Regeneration = re-run the script, commit. No CI, no external assets
  (the report is already self-contained; Pages adds a URL, nothing
  else).

Falsification tests: the build script is deterministic (same profiles
→ same bytes, modulo nothing — timestamps come from profile
provenance, not the build clock); the committed page matches a fresh
build in CI-less local check (a test rebuilds and compares); the page
names the probe version of every row.

## §6 The campaign

Runs LAST, after all instrument merges, exactly once.

- House wrapper (the amp2 pattern of record): `setsid nohup`, pid
  file, `.DONE` marker, `--expect-model-path`-style served-identity
  guard, SIGKILL + wait-for-port-down teardown between models, one
  model resident at a time (`ollama stop` between), VRAM-floor
  preflight, blob digests recorded per model.
- Full mode, `--record` transcripts, all **15 distinct**
  tier-enthusiast models, results → **new dated dir**
  `docs/superpowers/evidence/tier-enthusiast-2026-08/`. The old
  directory and its errata stand untouched — evidence is never
  rewritten.
- A ONE-model dry run first; extrapolate total hours against a stated
  stop rule before committing the night (preflight-before-hours).
- The same pass yields: the scripted-tools-v2 live anchor (one full
  sequential tools run recorded per the v1.6 anchor pattern), the
  parallel family's live rows for every model, and `assay diff`
  old-vs-new per model committed to evidence — which also
  hardware-verifies every geometry row the E1 sweep could only class
  unchanged-by-construction.
- GPU sharing: the box also serves bloomery sessions. The wrapper's
  preflight checks free VRAM against the floor and the campaign is
  scheduled with Brice's go for the night; it never kills another
  session's in-flight run.

## §7 Schema, versioning, discipline

- `PROFILE_VERSION = 8`, package **0.9.0**, bumped together with the
  pin test updated; README schema line and CHANGELOG entry in the
  same commit.
- All v8 additions parse-tolerate older profiles: `parallel` is a
  post-v1 family (absent → named in `dropped`); tools lens changes
  are lens content, not dataclass shape; new codec grades are new
  dict keys.
- `assay diff` compares across v6/v7/v8: absent-family and
  absent-grade cells read unmeasured on the old side, and the
  identity gate is untouched.
- TDD throughout; mutation checks on every load-bearing new test
  under the pyc discipline; CARRIED-DEBT.md appended at merge.
- Acceptance is §1–§6's falsification tests plus, campaign-side,
  pre-registered before launch: every new profile passes its own
  schema guard on parse-back; per-model diff runs clean through the
  identity gate; the matrix builds from all 15 fresh v8 profiles.

## §8 Deferred, with rulings

- Multi-turn tool chains / parallel calls: own wave (Brice, 08-17 —
  "sequential looks only").
- Tool-choice forcing: stands rejected (v1.6 §6 philosophy ruling).
- A `parallel` verdict: deferred until live rows exist to derive
  floors from — thresholds are derived, not chosen.
- Budget-mode wall-clock as a hard mid-call abort: rejected — a cut
  call is an uncontrolled instrument variable; between-calls is the
  honest granularity.
- Re-profiling `live/` / `live-run2/`: rejected — validation evidence
  of a dead daemon state; errata are the record.
