# assay v1.5 — the instrument sharpens itself

2026-08-14. Approved direction: first of three waves from the 08-14
brainstorm (v1.5 instrument-sharpening → v1.6 agent surface → v1.7
consumers + matrix). Ships as **0.6.0, profile schema v5**.

Three components: sequential testing for verdicts, `assay diff`, and a
long-output integrity probe. Each operationalizes a finding assay
already made or a debt it already recorded.

## §0 Scope and non-goals

In scope: verdict stopping rules, profile comparison/drift detection,
output-degeneration measurement, the schema and report changes they
require.

Non-goals (deferred to v1.6/v1.7 per the approved wave order):
tool-calling probe, loop error-recovery step, MoE-aware geometry,
time-budgeted quick-probe mode, parallel degradation, deeper JSON,
published matrix page. Also out: any change to codec fixtures or
lens definitions — v1.5 changes *how much* evidence verdicts demand
and *what happens between two profiles*, not what any probe measures.

## §1 Sequential testing

### What changes

Codec and loop cells currently run a fixed n (5 default, 35 under
`--thorough`) and verdicts are marked provisional when the Wilson 95%
interval fails to decide. v1.5 replaces fixed-n with a
**pre-registered look schedule**: trials run in blocks, and the cell
stops at the first look where the interval decides.

### Invariants

- **Look schedule: n ∈ {5, 10, 20, 35}.** Checked only at these
  points, never between them. Continuous peeking inflates
  false-decision rates; a fixed sparse schedule bounds the looks.
- **Stopping rule:** at a look, compute wilson95(passes, n). Stop
  `decided-ready` if lo ≥ ready-threshold; stop `decided-unusable` if
  hi < risky-threshold; otherwise continue. At n=35 undecided, the
  verdict stays `provisional` exactly as v1.3 defined.
- **The lens names the rule.** Every verdict produced under sequential
  testing carries `n_used` and
  `stopping_rule: "wilson95-looks-5-10-20-35"` in its lens. A verdict
  that stopped at n=5 is distinguishable from a v1.3 fixed-n=5 verdict
  by its lens, not by guessing from context.
- **Mode mapping (CLI already has `--quick`/`--full`/`--thorough`,
  default currently quick):** `--full` runs the sequential schedule
  and becomes the default mode; `--thorough` becomes an alias of full
  (its old meaning, n=35 flat, is subsumed — sequential runs to the
  same cap), kept for CLI compatibility and documented as such;
  `--quick` keeps fixed n=5 for time-boxed probes, its verdicts
  carrying the fixed-n lens. Mode budgets stay as they are; the
  BudgetMeter remains the outer bound.
- **Block boundaries are budget-checked.** The BudgetMeter is
  consulted before each block, same as every probe; a budget stop
  mid-schedule records the cell at its last completed look with
  `n_used` telling the truth.

### Amendment note (non-silent)

This amends v1.3's verdict semantics (spec of 2026-08-13: fixed n=5
with provisional marking; `--thorough` n=35 added in 0.4.1, sequential
testing recorded as deferred). The deferral is now executed. Old
profiles (schema ≤ v4) remain readable; their verdicts carry no
`stopping_rule` and are treated as fixed-n by `assay diff`.

### Falsification tests

- A cell at 5/5 with ready-threshold below wilson95(5,5).lo stops at
  n=5; the same passes with a higher threshold continues to n=10.
  (Mutate the look schedule → test fails.)
- A cell undecided at every look lands provisional at n=35 with
  `n_used=35`.
- Serialization completeness: `n_used` and `stopping_rule` survive the
  round-trip; a profile missing them parses as pre-v5.

## §2 `assay diff`

### What it is

`assay diff OLD.json NEW.json` — compare two profiles of the same
subject and report drift. This operationalizes the v1 live-validation
finding: capability is a point-in-time measurement of a serving state,
so the interesting object is the *difference between two timestamps*.

### Invariants

- **Identity gate first.** Comparable means: same model name, same
  blob digest (when both profiles carry one), same declared tier, same
  emulated/real-hardware marking. Any mismatch → exit 2
  ("not comparable"), no partial scoring. A missing digest on one side
  is a warning, not a mismatch.
- **What is compared:**
  - honest ceiling: any rung change reported, classified grew/shrank;
  - shape matrix: per-shape pass/fail flips;
  - verdict ladders: any flip (ready/risky/unusable, provisional
    status changes reported separately);
  - codec cells: rate change flagged **only when the two Wilson
    intervals are disjoint** — overlapping intervals are within noise
    and reported as such;
  - speeds: change beyond noise (below).
- **Speed noise is derived, not chosen — where possible.** The speed
  probe starts recording **per-call rates** (schema v5 addition:
  `samples` list per speed cell). Diff of two sampled cells uses a
  2-SE band on the difference of means. Against a pre-v5 profile with
  no samples, fall back to a fixed 20% relative threshold, and the
  output line says `threshold: 20% (assumed, not derived — pre-v5
  profile)`. The assumed number is marked for replacement once enough
  sampled profiles exist to derive run-to-run variance.
- **None-vs-zero.** A cell present in one profile and absent in the
  other goes in a `dropped` list ("not comparable at cell level") and
  is never scored as regression or improvement. Absence of evidence is
  absence, not zero.
- **Exit codes:** 0 = comparable, no drift beyond noise; 1 = drift
  found; 2 = not comparable. Infrastructure-style errors (unreadable
  file, schema too old to parse) raise with their own error class,
  never masquerade as exit 1.
- **`--gate` mode** (CI-shaped): only *worsening* drift — ceiling
  shrank, ladder dropped, speed fell, codec interval moved disjointly
  down — exits 1. Improvements print and exit 0. Direction of "worse"
  is defined per metric in one table in the module, not scattered.
- **Output:** human-readable text to stdout (same rendering discipline
  as `assay report`), `--json` for machine consumption.

### Falsification tests

- Two identical profiles → exit 0, empty drift list.
- Fabricated pair with a ceiling rung drop → exit 1; with `--gate` →
  exit 1; ceiling rung *rise* with `--gate` → exit 0.
- Disjoint-interval codec change flags; overlapping-interval change of
  the same magnitude does not. (Mutate the disjointness check → both
  tests cannot pass.)
- Identity mismatch (different digest) → exit 2 even when every cell
  would otherwise read clean.
- Real-data acceptance: diff of the two committed live-validation runs
  (`docs/superpowers/evidence/live` vs `live-run2`, same models, same
  day) must read **within noise** — those runs are the committed
  example of sampler-level variation that must not flag.

## §3 Long-output integrity probe

### Why

The v1 live validation observed (manual call, 15.8k prompt): protocol
held, stats intact, `done_reason: length` — and the output was
degenerate repetition. "Quality dies before protocol does." No current
probe measures this; a model can earn `ready` while emitting
repetition soup near its limits.

### What it does

A dedicated probe generates output at escalating target lengths —
rungs 512, 1024, 2048, 4096 tokens, capped by the measured ceiling and
the BudgetMeter — on a fixed task whose healthy output is naturally
non-repetitive (an enumeration task: distinct numbered items on a
seeded topic; exact prompt frozen in the module and named in the
lens). Each rung's output is scored with two stdlib metrics:

- **distinct-n ratio**: distinct 4-grams / total 4-grams;
- **zlib ratio**: len(compress(text)) / len(text).

### Invariants

- **Thresholds are derived from committed real data — and the
  anchor does not yet exist.** The known-degenerate 15.8k output was a
  manual call whose raw text was never committed (verified 2026-08-14:
  no committed transcript carries an `attention_loss` reply body).
  Therefore the implementation includes a **capture task**: reproduce
  degenerate output live (long-target generation on a small model is
  the expected path), commit the transcript under
  `docs/superpowers/evidence/degenerate-anchor/`, and derive
  thresholds from it against the committed healthy transcripts
  (`docs/evidence-transcripts/*.jsonl` reply bodies). Until the anchor
  is captured, thresholds ship marked `assumed, not derived` in the
  lens, and the verdict for this probe is capped at `provisional`.
  Synthetic repetition fixtures are smoke tests only — never the
  derivation source.
- **Real-data acceptance, once anchored:** the committed degenerate
  transcript must flag; a sample of committed healthy reply bodies
  must pass. Both are frozen regression tests; the anchor file is
  provenance and cannot drift.
- **Profile section `long_output`:** per-rung
  `{target_tokens, generated_tokens, distinct_n_ratio, zlib_ratio,
  degenerate: bool}`. Unreached rungs (budget, ceiling cap) are
  `None` and named in a `dropped` list — never zero.
- **Verdict `long_output`:** `ready` (no rung degenerate) /
  `degrades-at-N` (first degenerate rung named) / `unusable`
  (degenerate at the first rung). Lens carries both metric
  definitions, both thresholds, the task name, and the sampler.
- **Infrastructure vs subject:** a rung whose reply violates protocol
  (missing stats, non-200) raises as infrastructure and drops the
  rung; degeneracy is only ever scored on protocol-clean replies.
- **Report row:** `report.html` renders the verdict and the first
  degenerate rung; dashes for `None` per existing convention.

### Falsification tests

- A constructed high-repetition text scores below the distinct-n
  threshold and above the zlib-compressibility threshold (smoke,
  synthetic). A committed healthy reply body passes (real).
- Mutation: invert the degenerate boolean → verdict tests fail.
- Rung capping: ceiling lower than a rung → that rung `None` +
  dropped, not attempted.
- Serialization completeness for every new field.

## §4 Schema and versioning

- Profile schema **v5**: adds `long_output`, speed `samples`, verdict
  lens `n_used`/`stopping_rule`. Readers accept v1–v5; `from_json`
  treats missing new fields as absent (None), never defaults them to
  values that look measured.
- Package version 0.6.0. README version line updated (the twice-missed
  line has a test since 0.4.1; keep it green).
- CHANGELOG/README document the v1.3 amendment note verbatim.

## §5 Testing discipline

House rules apply in full: mutation-test every load-bearing behavior
under the pyc discipline (purge `__pycache__`,
`PYTHONDONTWRITEBYTECODE=1`); serialization round-trip with dataclass
equality + completeness; real-data acceptance anchored on committed
artifacts (live vs live-run2 for diff-within-noise; the captured
degenerate transcript for the integrity probe); no field defaults that
look like measurements. All tests green without a GPU; live capture is
the only step that needs the daemon, and it is an evidence task, not a
test.

## §6 Deferred, with rulings

- Alpha-spending / corrected interim intervals for the look schedule:
  deferred. The sparse pre-registered schedule bounds peeking; the
  lens names the rule; a formal correction is v-next if profile
  consumers ever need decision-theoretic guarantees.
- Deriving the speed-noise threshold from accumulated sampled
  profiles (replacing the assumed 20% fallback): deferred until ≥3
  sampled profiles per tier exist.
- Cross-model diff (comparing different models on the same tier):
  ruled out of `diff` — that comparison is `assay report`'s job.
