# assay v1.11 — the cover mode

2026-08-19. Derived from the bloomery seam spec
(`bloomery:docs/superpowers/specs/2026-08-19-swap-candidate-seam-design.md`,
§3 is the contract this document implements; scope decisions were
Brice-ruled in that spec's conversation). Ships as **0.13.0, profile
schema unchanged at v10**.

One component: `assay cover <floor.json> <candidate.json>` answers
whether a candidate profile **covers** a floor profile — whether the
candidate provides, at least as well, every cell the floor measured.
The wave's theme: the swap question is coverage, not drift. `diff`
refuses crossed model pairs by design (`model.name` is identity-fatal,
and rightly); `cover` is the comparison that crossed pairs actually
support.

## §0 Scope and non-goals

In scope: the `cover` subcommand, its identity rules, its per-cell
coverage semantics, its exit codes, render and `--json` document, and
the tests that pin all of it.

Non-goals: **no `--gate` flag** — cover IS a gate; its exit codes are
the whole point and there is no non-gate mode to distinguish.
**No change to `diff`'s semantics** — one shared-plumbing refactor
(§3's `_families`) moves code without changing behaviour, and the
existing suite pins that. **No schema change** — cover reads profiles,
it does not add to them. **No verdict for "the candidate is better"** —
coverage is one-directional and improvements are not evidence either
way. Consumption (bloomery's endpoint) is the seam spec's other half.

## §1 Identity: what must match, what may differ

`cover_identity_gate(floor, candidate)`, deliberately NOT `diff`'s
gate:

- **May differ, recorded as notes, never fatal:** `model.name`,
  `model.quant`, `model.weights_bytes`. Two different models is the
  point of the command.
- **Fatal (exit 2):** `provenance.tier` / `provenance.emulated`
  disagreement or one-sided absence — a floor measured on a different
  hardware class is not a floor for this box; same rule and same
  absent-is-fatal reasoning as `diff`'s gate.
- **Fatal (exit 2): instrument inequality.** `probe_version` and
  `assay_profile_version` must be **exactly equal** on both sides;
  absence on either side is equally fatal (an undeclared instrument is
  an unknown instrument).

> **Ruling (2026-08-19), amending the seam spec's §3 wording:** the
> seam spec listed "probe_version/schema mismatch, or a pair straddling
> a registered semantic break" as the instrument rule. Strict equality
> subsumes the straddle clause — equal versions cannot straddle — and
> strictness is the honest choice here: v1.10's own record states
> `SEMANTIC_BREAKS` is **not a complete inventory** of this project's
> rule changes, so a version-tolerant cover would be trusting an
> incomplete table with exactly the silent-pass failure the table was
> built to refuse. `diff` stays version-tolerant because its consumers
> (the drift watch) preequality-check versions themselves and a
> cross-version diff has legitimate uses; cover has one consumer and
> one question, and the floor can always be re-measured under the
> current instrument.

> **Amendment (2026-08-19, task-1 review ruling):** absence of
> `tier`/`emulated` on BOTH sides is also fatal — a deliberate
> deviation from `diff`'s gate, which passes that pair. Cover's own
> instrument loop already holds that undeclared is unknown, and a
> coverage claim "for this box" with no box declared on either side
> is the silent pass the gate exists to refuse. `diff` is unchanged.

## §2 Coverage: the per-cell rule

For every cell the **floor measured**:

- candidate ranks **greater-or-equal** on the cell's own scale →
  covered. Verdicts rank on the existing ladder (`unsupported` <
  `unusable` < `degrades-at-N` (higher N better) < `risky` < `ready`);
  numeric and rate cells use `diff`'s existing bases (Welch 2-SE bands
  when both sides carry samples, the assumed 20% threshold otherwise,
  Wilson-interval discipline for codec rates, exact rungs for
  ceilings).
- candidate ranks below, beyond the cell's noise discipline →
  **uncovered**.
- candidate did not measure the cell → **incomplete — never a pass**:
  the unmeasured cell may hide exactly the regression the check exists
  to catch.

Cells the candidate measured but the floor did not are **ignored**
(counted, named in the render, decisive of nothing): coverage is
one-directional. The `provisional` flags ride along in the evidence
and are never decisive — a floor cell is the floor whether or not its
Wilson interval had decided.

## §3 Mechanism: reinterpretation, not reimplementation

`diff` already compares every family cell-by-cell with the right noise
discipline and directions. Cover reuses that machinery whole:

- `diff.py` gains `_families(old, new) -> _Cells` — the five family
  walkers merged, extracted verbatim from `diff_profiles`'s body,
  which now calls it. A refactor with no behaviour change, pinned by
  the existing 1045-test suite.
- `cover.py` runs `_families(floor, candidate)` and reinterprets:
  a `Change` with direction `regression` is **uncovered**;
  `improvement` and `neutral` changes and every `within_noise` cell
  are **covered**; `dropped` cells split by which side measured them —
  floor-side → **incomplete**, candidate-side → **ignored**.
- Side-resolution uses no new naming logic: **a self-diff of the floor
  (`_families(floor, floor)`) puts exactly the floor's measured cells
  into `within_noise`, under the walkers' own names.** Membership in
  that set is the floor-side test, byte-for-byte consistent with the
  pair run by construction.
- `_families`' `incomparable` field (probe_version straddling a
  registered break) is unreachable under §1's strict equality; cover
  still checks it and refuses (exit 2, naming the cells) rather than
  assuming — defense against a future caller loosening §1.

## §4 Exit codes, render, `--json`

`0` covered, `1` not covered, `2` refused (identity or instrument),
`3` incomplete, precedence **2 > 3 > 1 > 0** — mirroring `diff --gate`
so a consumer's four-code reading maps over unchanged.

The render names every uncovered cell with both values, every
incomplete cell, the ignored-count, and the identity notes. `--json`
writes the whole `CoverResult` via the same `asdict` route `diff`
uses, and the document carries `uncovered`, `covered`, `incomplete`,
`ignored`, `incomparable`, `identity_notes`, `comparable` — each list
explicitly, so a consumer never re-derives a verdict from prose
(`incomparable` is the defense-in-depth field of §3, present and empty
under the strict gate).

## §5 Testing posture

House rules (TDD; mutation-check load-bearing tests):

- The reinterpretation table enumerated: regression→uncovered,
  improvement→covered, neutral→covered, within-noise→covered,
  floor-side dropped→incomplete, candidate-side dropped→ignored.
- The incomplete rule is load-bearing: a candidate covering every
  measured cell but missing one floor cell exits 3, never 0.
- One-directionality pinned: a candidate-only cell changes no exit.
- Identity pins: crossed model names pass the gate (the inversion);
  tier mismatch refuses; probe_version inequality refuses even when
  every cell would have covered.
- The `_families` extraction pinned by the existing diff suite
  (behaviour unchanged) plus one direct test that re-derives the
  expected cells from the five walkers independently, on a pair that
  differs — so a walker dropped or reordered inside `_families` fails
  it (amended 2026-08-19: an earlier wording described a
  diff_profiles-vs-_families comparison, which after the refactor is
  a tautology).
- Exit precedence enumerated as a table, like `diff`'s.
