# assay v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build assay v1 — a stdlib-only library + CLI that probes a locally-served LLM endpoint (geometry, empirical ceiling, envelope fidelity, codec landing) and emits the versioned capability profile defined in `docs/superpowers/specs/2026-08-12-assay-v1-design.md`.

**Architecture:** Four probe families (geometry / ceiling / envelope / codecs) over two backends (Ollama-native, OpenAI-compat) behind one `Backend` protocol, feeding one versioned `Profile`. Record/replay wraps any backend so the whole suite tests GPU-free.

**Tech Stack:** Python 3.12+, stdlib only at runtime (`urllib`, `json`, `hashlib`, `subprocess`, `random`, `dataclasses`). Dev-only: `pytest`.

## Global Constraints

Copied from the spec; every task's requirements include these.

- Python 3.12+; **zero runtime dependencies**; synchronous `urllib` HTTP.
- Package layout: `src/assay/`; installable (`pip install -e .`); CLI entry point `assay`.
- **None-vs-zero (spec §8):** unmeasured is `None` and named in `provenance.dropped`; measured-and-zero is `0.0`. Never conflate. No field may default to a value that looks like a measurement.
- **No grammar/JSON forcing in any probe** (spec §0): probes measure unforced behavior.
- **Determinism:** all randomness via `random.Random(seed)` passed explicitly; wall-clock appears only in provenance.
- **Error taxonomy (spec §3):** infrastructure failures raise; model behavior (refusal, rambling, wrong format) is DATA, never an exception.
- **Every new test is mutation-tested** before its task's commit: break the code the test pins (delete/invert the core line), verify the test FAILS, restore. A test that survives its mutation is a defect in the test. The named review item for every task: *a value that looks like a measurement but is not*.
- License MIT. Git identity is already configured repo-locally.
- Commit style: conventional commits (`feat:`/`fix:`/`docs:`/`test:`), no attribution footers.

**House plan style (robigo CARRIED-DEBT lesson 1):** tasks below state exact interfaces plus invariants with their falsification tests. Code blocks are given where a fresh implementer would plausibly guess wrong (algorithms, wire formats, applier semantics). Where a step says "invariant → test", the test named MUST exist and MUST be mutation-tested; its exact assertion body is the implementer's to write against the stated invariant.

### Task 7: Ceiling probe

**Files:**
- Create: `src/assay/ceiling.py`

**Interfaces:**
- Consumes: `Backend`, `BudgetMeter`, `Reply`, errors.
- Produces:
```python
@dataclass(frozen=True)
class Calibration:
    chars_per_token: float | None
    counts_available: bool
    deterministic: bool | None   # two identical seeded calls, same text?

@dataclass(frozen=True)
class CallEvidence:
    est_tokens: int; seed: int; signal: str; detail: str

@dataclass(frozen=True)
class Ceiling:
    max_verified: int | None
    first_failure: int | None
    failure_mode: str   # hard_error|missing_stats|silent_truncation|canary_loss|none_up_to_cap
    counts_available: bool
    evidence: tuple[CallEvidence, ...]

def build_filler(rng: random.Random, est_tokens: int, chars_per_token: float) -> str
def calibrate(backend, meter, *, seed: int) -> Calibration
def classify_call(outcome: Reply | Exception, *, sent_est: int, canary: str,
                  counts_available: bool) -> str
def probe_ceiling(backend, meter, *, cap_tokens: int, seeds: Sequence[int],
                  calibration: Calibration) -> Ceiling
```

**Algorithm (spec §5), pinned:**
1. `build_filler`: seeded choices from a fixed ~200-word list embedded in the module (natural words, mixed lengths — one repeated token tokenizes unrepresentatively), joined with spaces, sized to `est_tokens * chars_per_token` chars.
2. `calibrate`: one ~500-token probe (`chars_per_token` seed value 3.0), canary prompt as below; `chars_per_token = len(prompt) / tokens_in` when counts exist, else `None` and 3.0 is used for all sizing. Then one repeat of the same seeded call: `deterministic = (text1 == text2)` when both succeed, else `None`.
3. Canary prompt (exact):
   ```
   Begin your reply with exactly the word ASSAY-{seed}. That word must be
   the very first token of your reply.

   {filler}
   ```
4. `classify_call` decision table, in this order:
   - `InfrastructureError` that is a `ContractViolation` → `"missing_stats"`
   - any other `InfrastructureError` → `"hard_error"`
   - `tokens_in` present and `< 0.8 * sent_est` → `"silent_truncation"`
   - canary absent from the start of `text` and `tokens_in` present and `>= 0.8 * sent_est` → `"attention_loss"` (a MODEL result: recorded as evidence, is NOT a failure, does NOT stop the ladder)
   - canary absent and counts unavailable → `"canary_loss"`
   - else → `"ok"`
5. Ladder: sizes 1024, doubling while `size <= cap_tokens`, each size × each seed (default seeds `(0, 1)`); a size **fails** when any seed's classification is in `{hard_error, missing_stats, silent_truncation, canary_loss}`. First failing size stops the ladder.
6. Bisection between last-ok and first-fail until `hi - lo <= max(lo // 10, 256)` or the meter runs dry (`BudgetExhausted` from `meter.charge` propagates only if NOTHING was measured yet; otherwise caught, recorded in evidence as `"budget"`, and the ceiling reports what it verified).
7. `failure_mode` = classification of the smallest failing size (majority across its seeds; ties → the first in the table order). All-ok up to cap → `"none_up_to_cap"`, `first_failure=None`.

- [ ] **Step 1: Failing tests for `classify_call`** (pure function first): one test per table row, plus `test_attention_loss_requires_counts_that_contradict_truncation` (canary absent + counts ≈ sent ⇒ attention_loss, not canary_loss).
- [ ] **Step 2: FAIL. Step 3: implement `classify_call` + `build_filler` (+ its test: `test_filler_is_seed_deterministic_and_sized`). Step 4: PASS.**
- [ ] **Step 5: Failing tests for the ladder** against scripted fake backends:

  - `test_missing_stats_fake_reproduces_the_ollama_bug` — fake raises `ContractViolation` above 11500; mode `missing_stats`, `max_verified <= 11500 < first_failure`.
  - `test_honest_server_reports_none_up_to_cap`.
