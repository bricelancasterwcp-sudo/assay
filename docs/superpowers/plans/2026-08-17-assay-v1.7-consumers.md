# assay v1.7 — consumers and the matrix — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the v1.7 consumers wave — tools sequential looks (scripted-tools-v2), deeper JSON grades, the parallel family, budget mode, the published matrix — then re-profile all 15 tier models once and publish the matrix on GitHub Pages.

**Architecture:** Six components land as instrument changes behind one schema bump (v8, package 0.9.0), then a single OS-detached campaign probes every tier model with the finished instrument and the matrix publishes from those fresh profiles. Nothing GPU-expensive runs twice.

**Tech Stack:** Python 3.12+ stdlib only (urllib, json, threading), pytest (scratchpad venv — no repo venv, no system pytest), Ollama daemon on this box, gh CLI for the Pages step.

**Spec:** `docs/superpowers/specs/2026-08-17-assay-v1.7-consumers-design.md` — the plan argues from it; read both. House context: `docs/superpowers/specs/2026-08-15-assay-v1.6-design.md` §6 rulings still bind.

## Global Constraints

- **TDD, strictly**: failing test first, watch it fail, minimal green. Mutation-check every load-bearing new test (break the pinned line → test FAILS → restore) under the pyc discipline: purge `__pycache__` before every run and set `PYTHONDONTWRITEBYTECODE=1`.
- **Test environment**: no system pytest / no repo venv — `python3 -m venv <scratchpad>/assay-venv && pip install -e <repo> pytest`, run `python -m pytest` from the repo root. NEVER wrap anything in `timeout` (uutils segfault, exit 139 = the wrapper crashed).
- **None-vs-zero**: unmeasured is `None` and named in `dropped`; measured-and-zero is `0`/`0.0`. No field may default to a value that looks like a measurement.
- **Frozen surfaces**: `TOOLSET`/`TOOLSET_NAME` (toolset-v1), the v2 codec fixtures and `JSON_TASKS` bytes, tasks 0–4 of the tools pool, every committed profile and evidence file. Evidence is never rewritten.
- **Versioning**: all shape changes ride ONE bump — `PROFILE_VERSION = 8`, package `0.9.0` — in Task 10 only. Tasks 1–9 must not bump.
- **Commit style**: single-line conventional commits, no attribution trailers. Push only at the wave points named in tasks; verify origin sync after every push (`git rev-parse master origin/master | uniq -c` → one line).
- **GPU**: the box is shared (bloomery sessions). Tasks 1–11 are CPU-only. Tasks 12–14 touch the daemon; only `/api/show`-class metadata calls before the Task 12 gate, and never kill another session's run.

### Task 5: The parallel instrument

**Files:**
- Create: `src/assay/parallel.py`
- Test: `tests/test_parallel.py` (new)

**Interfaces:**
- Consumes: `Backend.generate` (the same call speed.py makes), `assay.speed`'s server-timing extraction (import the helper speed.py uses to turn a reply into decode tok/s; if it is inline there, extract it to a shared function `decode_tps_from(reply)` in speed.py FIRST, with speed's tests green), `BudgetMeter`, `DECODE_PROMPT`.
- Produces:

```python
OVERLAP_TOLERANCE_S = 0.25  # CHOSEN, not derived — sanity-checked by
                            # the campaign's live rows (spec §3)
TOLERANCE_PROVENANCE = "chosen-2026-08-17"

@dataclass(frozen=True)
class ParallelRow:
    k: int
    per_lane_decode_tps: float | None   # None = no lane reported timings
    total_throughput_tps: float | None
    degradation_ratio: float | None     # per-lane / single-lane baseline
    mode: str | None                    # "parallel" | "serialized" | None
    n_lanes_ok: int
    lane_errors: tuple[str, ...]        # named infra failures, never zeros
    evidence: str                       # timing-evidence class, speed.py's vocabulary

@dataclass(frozen=True)
class Parallel:
    rows: tuple[ParallelRow, ...]
    baseline_decode_tps: float
    tolerance_s: float                  # == OVERLAP_TOLERANCE_S as run
    tolerance_provenance: str           # == TOLERANCE_PROVENANCE

def probe_parallel(backend, meter, *, baseline_decode_tps: float,
                   ks: tuple[int, ...] = (2, 4), seed_base: int = 1700,
                   clock=time.monotonic, runner=None) -> Parallel
```

Behavior contract:
- Per k: charge the meter for k calls FIRST (all-or-nothing: if `would_exceed`, the k-row is skipped and named in the row-less return path — see below), then launch k threads each sending `DECODE_PROMPT` with seed `seed_base + k*10 + lane`, `max_tokens` matching speed's decode probe. `runner` is the injection seam: `runner(callables) -> list[(start_s, end_s, reply_or_exc)]`; default implementation uses `threading.Thread` and records `clock()` immediately before/after each lane's call.
- `mode`: sort lane spans by start; `"serialized"` iff every consecutive pair overlaps less than `OVERLAP_TOLERANCE_S` (i.e., `next.start >= prev.end - tolerance`); `"parallel"` otherwise; `None` when fewer than 2 lanes returned. Client clocks decide ONLY this scheduling fact.
- Rates from server timings via the shared extractor; a lane whose reply lacks timings contributes to `n_lanes_ok` but not to tps means, and the row's `evidence` names the weakest class among lanes. A lane raising is caught, named in `lane_errors`, excluded from means; ALL lanes erroring → that k-row has every rate None and `mode=None`.
- `BudgetExhausted` before any k → propagate (run.py drops the family by name). Baseline is the caller's obligation (run.py passes `speed.decode_tps`; the family never runs without it).

- [ ] **Step 1: Failing tests** — synthetic runner returning pinned spans/replies: (a) stacked spans (gaps > tolerance? no — stacked = sequential) classify `serialized`; overlapping spans classify `parallel`; both sides of the tolerance pinned to the second decimal; (b) degradation arithmetic pinned (`per_lane 30.0` vs baseline `60.0` → ratio `0.5`); (c) one lane raises → named in `lane_errors`, mean over the rest; (d) all lanes raise → rates None, mode None, never 0.0; (e) missing timings → evidence class named, tps None; (f) meter refusal on k=4 after k=2 ran → rows contain k=2 only.
