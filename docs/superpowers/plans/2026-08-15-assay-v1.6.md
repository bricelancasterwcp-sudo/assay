# assay v1.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship assay 0.7.0 (profile schema v6): native tool-calling probe, loop error-recovery script, MoE-aware geometry metadata, and the v1.5 consolidation debt.

**Architecture:** One new backend method (`chat_tools`) on both backends plus recorder/replayer support; a new `tools.py` probe family; an error script added to `loop.py`; metadata additions threaded through `ModelInfo`/`geometry.py`; profile/run/diff/report integration as schema v6. The consolidation task runs first so later tasks build on the shared stop-lens registry.

**Tech Stack:** Python stdlib only (hard rule). pytest; fakes in `tests/fakes.py`; no GPU/network in the suite. Live capture only in the final task.

**Spec:** `docs/superpowers/specs/2026-08-15-assay-v1.6-design.md` — the binding authority; read it first.

## Global Constraints

- stdlib only; no new dependencies.
- All tests pass with no GPU and no network (suite currently 447 tests, ~0.7s).
- None-vs-zero: unmeasured is `None` + named in `provenance.dropped`; `supported=False` rates are `None` (refused, not zero); a dense model's expert fields are `None`, never 0.
- Every verdict names its lens; new lens fields appear in round-trip AND completeness tests.
- Mutation-check load-bearing behavior under the pyc discipline (`find . -name __pycache__ -exec rm -rf {} +`; `PYTHONDONTWRITEBYTECODE=1`).
- Conventional commits; commit per task minimum.
- Version 0.7.0 in BOTH `pyproject.toml` and `src/assay/__init__.py`; `PROFILE_VERSION = 6`. README version lines have tests — keep green.
- House constants: thresholds ready 0.9 / risky 0.6; `PROBE_TEMPERATURE = 0.2`; every probe call charges the meter before generating.
- Budget arithmetic (Task 7 recomputes the cli.py comments): tools family = 10 calls (5 tasks × 2 turns); error script = 2 × `loop_runs`. Quick worst case becomes 93+10+6 = **109 of 110 — the quick budget MUST be raised** (to `Budget(max_calls=130, max_prompt_tokens=220_000)`); full becomes 391+10+10 = 411 of 500, no raise.
- Environment note for implementers: no system pytest / no repo venv — build one in the session scratchpad (never in the worktree), `pip install -e` the worktree + pytest.

**Files:**

**Interfaces (Produces):**

```python
# base.py
@dataclass(frozen=True)
class ToolCall:
    name: str
    arguments: dict | None   # None = arguments present but unparseable (DATA)

@dataclass(frozen=True)
class ToolReply:
    text: str
    tool_calls: tuple[ToolCall, ...]
    tokens_in: int | None
    tokens_out: int | None
    stop_reason: str | None
    raw: dict

class ToolsUnsupported(Exception):
    """The endpoint refused the tools parameter — a CAPABILITY FACT the
    probe records, never an infrastructure failure. Carries .raw."""

# Backend protocol gains:
def chat_tools(self, messages: list[dict], tools: list[dict], *,
               seed: int, max_tokens: int) -> ToolReply: ...
```

**Invariants (the guess-wrong parts, verbatim):**
- **Unsupported classifier** (one function in base.py, both backends call it): a 4xx status whose body's error string contains `"tool"` (case-insensitive) → raise `ToolsUnsupported` with the raw body. Any other non-2xx → `InfrastructureError`. The rule keys on behavior class, not exact wording (error text is not a stable target — Ollama says "does not support tools", others vary).
- Ollama `chat_tools`: `POST /api/chat` with `{model, messages, tools, stream: False, think: False, options: {seed, num_predict, temperature: PROBE_TEMPERATURE}}`. Parse `message.content` (may be `""`), `message.tool_calls[*].function.{name, arguments}` — Ollama's `arguments` is already a dict. Counts from `prompt_eval_count`/`eval_count`, stop from `done_reason`; `validate_reply`'s count contract applies (build a Reply-shaped check or validate the fields directly with the same rule).
- OpenAI `chat_tools`: `POST {base}/chat/completions` with `{model, messages, tools, max_tokens, seed, temperature}`. `tool_calls[*].function.arguments` is a JSON **string**: `json.loads` it; on failure the ToolCall gets `arguments=None` (DATA, never raises). **Refactor required first:** `_read_json` currently raises `InfrastructureError` on HTTPError, discarding the body the classifier needs — change it to return `(code, body)` like Ollama's `_send` (body `{}` if unreadable), and move the non-200 raise into `generate` (behavior there unchanged — pin with the existing tests). `chat_tools` then classifies via the shared function.
- Empty/absent `tool_calls` → `tool_calls=()` with the text answer in `text` — a model answering in prose instead of calling is DATA the probe scores, not an error.

```python
                       "properties": {"path": {"type": "string"}},

    {"type": "function", "function": {

        "description": "Run the project's test suite.",
        "parameters": {"type": "object", "properties": {},

    {"type": "function", "function": {
        "name": "search_docs",
        "description": "Search the documentation for a term.",
        "parameters": {"type": "object",
                       "properties": {"query": {"type": "string"}},
                       "required": ["query"]}}},
]
# Five tasks: (user message, expected tool, expected args or None)
TASKS = (
    ("Open the file `config.yaml` and show me what is in it.",
     "read_file", {"path": "config.yaml"}),
    ("Check whether the test suite passes right now.",
     "run_tests", {}),
    ("Find what the documentation says about `retry_policy`.",
     "search_docs", {"query": "retry_policy"}),
    ("Read `src/main.py` for me.",
     "read_file", {"path": "src/main.py"}),
    ("Look up `rate limiting` in the docs.",
     "search_docs", {"query": "rate limiting"}),
)

@dataclass(frozen=True)
class Tools:
    supported: bool | None        # None = never attempted; False = refused
    call_rate: float | None       # exactly-one-call over scored T1s
    right_tool_rate: float | None
    args_valid_rate: float | None
    result_use_rate: float | None # canary echoed, no spurious call, over scored T2s
    composite: float | None       # per-task AND of the three T1 criteria
    n_tasks: int
    n_turns: int

def probe_tools(backend, meter, *, seed_base: int = 1400) -> Tools: ...
```

**Invariants:**
- T1 messages: a short system line naming the assistant a tool-using helper + the task's user message; `TOOLSET` passed as tools. Scoring: `call_rate` counts len(tool_calls)==1; `right_tool_rate` counts name match (over T1s that called at all); `args_valid_rate` counts schema-valid AND expected-value match where the task pins one (`{}` means must be empty/absent-of-required); composite = one call AND right tool AND valid args.
- T2 messages: T1's messages + a canned assistant message carrying the GOLDEN call (not the model's) + a `role: "tool"` result whose content embeds the canary `f"CANARY-{seed}"` — scripted, zero branching. Scoring: `result_use_rate` counts canary substring present in `text` AND `tool_calls == ()`.
- `ToolsUnsupported` on the FIRST call → `Tools(supported=False, all rates None, n_tasks=0, n_turns=0)`; the probe stops (no point burning 9 more refusals). Infrastructure propagates. Budget death yields honest partial n (rates over scored turns) — same shape as every probe.
- Seeds: `seed_base + task_index` for T1, `seed_base + 100 + task_index` for T2 (distinct, deterministic; document in the module).
- Meter charge per call: `max(1, len(canonical_messages_json) // 4)` where canonical is the Task 3 serialization — state it in the docstring.

**Files:**

**Invariants:**
- `LOOP_INSTRUMENT` becomes `"scripted-loop-v2"` (the lens change IS the amendment). The golden 3-turn script is unchanged. New error script, 2 turns per run: T1 = the golden T1 (expect `read`); T2′ prompt (verbatim structure — build from the existing `_envelope`):

```
<envelope>
> read tiny.py

Contents of `tiny.py`:
<original>

> patch tiny.py
<the CANNED BROKEN patch: a SEARCH/REPLACE block whose SEARCH lines are
 the correct target lines with ALL LEADING INDENTATION STRIPPED — the
 measured qwen signature; build it from the fixture's real lines>

The patch FAILED to apply: SEARCH text not found in `tiny.py`.

Contents of `tiny.py` (unchanged):
<original>

Your next action:
```

- Scoring: **recovery** = reply is `patch tiny.py` whose payload applies (`apply_search_replace`) and parses; **doom loop** = the reply's SEARCH lines, whitespace-normalized (`" ".join(line.split())` per line), equal the canned broken SEARCH's normalized lines. A reply can be neither (e.g. `read` again — scored as no-recovery, no-doom).
- `Loop` gains `recovery_rate: float | None`, `doom_loop_rate: float | None` — None when the error script never ran; rates over completed error runs. Error runs use seeds `seed_base + 50 + run` (distinct from golden runs). Error-script T1 replies also count toward `action_fidelity`/repeat/anchor scoring (they are scored turns of the same instrument).
- Budget: error runs charged like golden turns; a budget death mid-error-script keeps golden results and reports recovery honestly partial or None.
